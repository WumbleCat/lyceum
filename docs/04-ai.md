# 04 · AI

Three narrow jobs, each a Supabase edge function. Every job takes JSON, returns JSON, and has its output validated against a schema before anything is stored. On a validation failure, retry once, then fall back as described.

Keep the provider, model names and keys in environment variables. Use a stronger model for job 1 and a smaller, cheaper one for jobs 2 and 3. Check the provider's current documentation for model names and structured-output support; do not assume any from this file.

## Job 1 · Next question

Decides what to ask next and writes the question.

Input:

```json
{
  "belief": "Palantir is doing more harm than good.",
  "claim_types": ["ethical"],
  "agreement": 65,
  "founded": 40,
  "why": "the person's own explanation",
  "based_on": ["heard"],
  "mode": "clarify",
  "length": "quick",
  "focus_node": null,
  "turns": [
    { "stage": 1, "family": "familiarity", "question": "...", "answer": { "picked": ["I know the basics"] } }
  ],
  "nodes": [
    { "type": "reason", "text": "...", "source": "user_picked", "confirmed": true }
  ]
}
```

Output:

```json
{
  "stage": 3,
  "family": "reasoning",
  "format": "multi",
  "question": "Which considerations most influence your position?",
  "hint": "Pick all that apply.",
  "options": ["...", "...", "...", "...", "I'm not sure"],
  "is_last": false
}
```

Rules for the prompt:

1. Pick the stage and family that addresses the biggest gap in the reasoning so far:
   - Low familiarity: clarify the subject first.
   - Unclear terms: ask for a definition.
   - Relies on intuition: ask where it came from.
   - Anecdotal evidence: ask whether the examples are representative.
   - Strong conclusion, thin support: ask about the assumptions underneath.
   - Well supported: ask about limits, counterexamples and other views.
   - Competing values: ask how the person weighs the trade-off.
2. Never repeat a family already asked unless the earlier answer was skipped.
3. Neutral wording. Do not presume a motive or that the belief is wrong. Bad: "Why do you dislike X?" Good: "Which consideration most influences your position?"
4. Options must include considerations on more than one side where sides exist.
5. Two to five options. Always include an uncertainty option such as "I'm not sure" or "It depends".
6. `format` is `open` when choices would put words in the person's mouth. Then `options` is empty.
7. Quick sessions end after three answered questions. Deep sessions end when stage 5 has been covered. Set `is_last` on the final question. Stage 6 is the Synthesis screen and needs no generated question.
8. When `focus_node` is set, every question is about that node.
9. Follow the mode: clarify, other_side, evidence, strongest.
10. Do not state facts about real people or organisations inside a question or its options. Ask what the person understands instead.
11. Questions are under 25 words. Options are under 8 words.

Fallback when the model fails twice: serve the next unused family from this fixed order with its generic wording from `docs/01-product.md`: familiarity, origin, reasoning, scope, reconsideration.

The first questions for the daily statement are generated once when the statement is approved and stored in `daily_statements.opening_questions`, so the first question is instant and costs nothing per person.

Generate the next question in the background as soon as the current one is shown, for each likely answer if that is cheap enough, so the person rarely waits.

## Job 2 · Extractor

Turns one answered turn into changes to the map.

Input: the belief, the turn just answered, and the current nodes and edges.

Output:

```json
{
  "add_nodes": [
    { "temp_id": "n1", "type": "reason", "text": "Privacy and surveillance", "source": "user_picked" },
    { "temp_id": "n2", "type": "assumption", "text": "Privacy harms outweigh the benefits of the technology.", "source": "athena_guess" }
  ],
  "add_edges": [
    { "from": "n1", "to": "main", "relation": "supports" },
    { "from": "n2", "to": "n1", "relation": "depends_on" }
  ]
}
```

Rules for the prompt:

1. `source` is `user_picked` for a chosen option, `user_said` for the person's own words, and `athena_guess` for anything inferred.
2. Text for `user_said` nodes stays close to the person's own wording.
3. At most one `athena_guess` per turn, and only when the answer clearly rests on an unstated premise.
4. Picking an option is not an argument. Do not invent detailed reasons the person never gave.
5. Do not duplicate a node that already exists.
6. An empty result is valid.

The server sets `confirmed = false` on every `athena_guess` regardless of what the model returns.

## Job 3 · Sorter

Runs after a belief is created or revised.

1. Embed the latest version's statement and store it.
2. Category: compare with the person's existing categories. Return an existing category name, or propose a new short name with an `icon_key` from the fixed list in `docs/02-design.md`. A belief may get up to two categories.
3. Connections: find the person's other beliefs with high embedding similarity. For each candidate, ask the small model whether the two may be related and return a one-line neutral description. Store as `connections` with `status = 'suggested'`.

Output:

```json
{
  "categories": [{ "name": "Technology", "is_new": true, "icon_key": "technology" }],
  "connections": [{ "belief_id": "...", "shared_text": "Both weigh privacy against public benefit." }]
}
```

Rules:

1. Never say two beliefs contradict each other. Use "may relate to" or "may pull against".
2. At most one new connection suggestion surfaced per day.
3. Prefer an existing category when it fits. New categories are one or two words.

## Recap text

The "Where it holds together" box on the recap screen is written by the job 1 model in a separate short call. Two sentences: one on what is consistent in the person's reasoning, one on what has not been examined yet. No verdict on whether the belief is right.

## Daily statements

- Generate a batch of candidates offline with claim types and a suggested category.
- A human approves each one before it gets a publish date.
- Wording is neutral and names no private individual.
- Mix the six claim types across a week.

## Safety and trust

1. Athena does not give its own opinion on contested political or ethical statements. It asks questions.
2. If the person cannot define the subject, Athena may offer a short background note. Until evidence search with sources is built, label that note as general background that may be out of date, and keep it to uncontested basics.
3. Beliefs are sensitive personal data. Do not log request bodies. Do not send more of the person's history to the model than the job needs.
4. Check the provider's data-use terms and choose settings so that people's beliefs are not used for training.
5. If an answer suggests the person may be in distress or at risk, stop the questioning flow and show a supportive message with a pointer to appropriate help. Design this path with care before launch.

## Cost controls

- Cache the daily statement's opening questions.
- Small model for jobs 2 and 3.
- Cap Deep sessions per day on a free tier.
- Record tokens and cost per dialogue so "AI cost per completed reflection" can be measured from the first day.
